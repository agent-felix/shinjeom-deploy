## Database and rollout compatibility

Production started at `f18c6a43e0b7`, with no plot, text-consult billing or rating tables. The existing localization migration therefore had no existing production chat rooms to clear. The Helm migration hook completed all pending migrations through `f82d3a0b5c41`. Staging advanced from `e71c2f9a4b30` to the same head.

Commit `6593ee4` adds a follow-up migration retaining `false` as the database default for `users.has_seen_text_consult_menu_badge`. This lets older API pods continue inserting users during the rolling upgrade or application rollback. It preserves existing badge values and leaves already-deployed migration files unchanged.

## Rollback reference

The previous production application is `shinjeom-api-v2.3.6`, Helm revision 36. An application rollback does not downgrade the database. The new badge default supports old-pod signup compatibility. If the API is rolled back, disable Faceless usage admission as well because the older API does not expose its usage endpoints. Avoid database downgrade operations that remove new plot/billing data.
